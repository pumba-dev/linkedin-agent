## Referência

- GitHub Octoverse: 43,2 milhões de pull requests mesclados por mês (+23% a/a) e quase 1 bilhão de commits no ano (+25%).
- Levantamentos de 2026 sobre times com IA no fluxo: ~98% mais pull requests abertos e ~91% de aumento no tempo de revisão; PR assistido por IA espera ~4,6x mais até alguém iniciar a revisão.
- Tese própria: acelerar não é revisar mais rápido, é baratear o custo de entender a intenção.

## Texto

Times que adotaram IA no fluxo abrem quase o dobro de pull requests. O tempo de revisão subiu quase na mesma proporção.

O gargalo mudou de lugar.

Escrever código ficou barato. Entender código continua custando o mesmo.

Um número resume bem isso. Pull request gerado com ajuda de IA espera cerca de quatro vezes mais até alguém abrir. Depois que abre, a revisão corre rápido. A fila é que não anda.

Faz sentido quando se olha o que revisar realmente exige. Ler o diff é a parte fácil. O trabalho pesado é reconstruir a intenção, entender por que aquela decisão foi tomada e o que ela move três camadas abaixo.

Quando a geração acelera e o contexto não vem junto, cada revisor refaz esse raciocínio do zero.

O que tenho visto funcionar não é revisar mais rápido. É baratear o entendimento.

Pull request pequeno, com uma mudança só. O porquê escrito junto do código, não apenas o que mudou. E a primeira passada no superficial (estilo, teste faltando, caso de borda óbvio) pode ser automatizada, para que a atenção humana fique onde é insubstituível, na arquitetura e na regra de negócio.

Quem escreve a intenção junto com o código multiplica a velocidade de todo mundo em volta.

Desde que a IA entrou no seu fluxo, o que mudou na forma como vocês revisam?
